## 概要

Codex-CLIのツールシステムは、AI エージェントが実行できる機能を型安全かつ柔軟に定義・管理するアーキテクチャを提供します。このシステムは、内蔵ツール、外部MCPツール、モデル固有のツール形式を統一的に扱います。

### アーキテクチャの特徴
- **統一型システム**: 異なるツール形式の透明な統合
- **動的構築**: 設定とモデル特性に基づくツール選択
- **拡張可能性**: MCP（Model Context Protocol）による外部ツール統合
- **型安全性**: Rust型システムによる厳密な検証

```rust
pub(crate) struct ToolsConfig {
    pub shell_type: ConfigShellToolType,
    pub plan_tool: bool,
    pub apply_patch_tool_type: Option<ApplyPatchToolType>,
    pub web_search_request: bool,
}

impl ToolsConfig {
    pub fn new(params: &ToolsConfigParams) -> Self {
        let shell_type = if *use_streamable_shell_tool {
            ConfigShellToolType::StreamableShell
        } else if model_family.uses_local_shell_tool {
            ConfigShellToolType::LocalShell
        } else {
            ConfigShellToolType::DefaultShell
        };

        // 承認ポリシーに基づく調整
        if matches!(approval_policy, AskForApproval::OnRequest) && !use_streamable_shell_tool {
            shell_type = ConfigShellToolType::ShellWithRequest {
                sandbox_policy: sandbox_policy.clone(),
            }
        }

        // Apply Patchツール型の決定
        let apply_patch_tool_type = match model_family.apply_patch_tool_type {
            Some(ApplyPatchToolType::Freeform) => Some(ApplyPatchToolType::Freeform),
            Some(ApplyPatchToolType::Function) => Some(ApplyPatchToolType::Function),
            None => {
                if *include_apply_patch_tool {
                    Some(ApplyPatchToolType::Freeform)
                } else {
                    None
                }
            }
        };
    }
}
```

### メインツール構築関数

**`get_openai_tools`** (openai_tools.rs)
```rust
pub(crate) fn get_openai_tools(
    config: &ToolsConfig,
    mcp_tools: Option<HashMap<String, mcp_types::Tool>>,
) -> Vec<OpenAiTool> {
    let mut tools: Vec<OpenAiTool> = Vec::new();

    // シェルツールの選択
    match &config.shell_type {
        ConfigShellToolType::DefaultShell => {
            tools.push(create_shell_tool());
        }
        ConfigShellToolType::ShellWithRequest { sandbox_policy } => {
            tools.push(create_shell_tool_for_sandbox(sandbox_policy));
        }
        ConfigShellToolType::LocalShell => {
            tools.push(OpenAiTool::LocalShell {});
        }
        ConfigShellToolType::StreamableShell => {
            tools.push(OpenAiTool::Function(
                crate::exec_command::create_exec_command_tool_for_responses_api(),
            ));
            tools.push(OpenAiTool::Function(
                crate::exec_command::create_write_stdin_tool_for_responses_api(),
            ));
        }
    }

    // Apply Patchツールの条件付き追加
    if let Some(apply_patch_tool_type) = &config.apply_patch_tool_type {
        match apply_patch_tool_type {
            ApplyPatchToolType::Freeform => {
                tools.push(create_apply_patch_freeform_tool());
            }
            ApplyPatchToolType::Function => {
                tools.push(create_apply_patch_json_tool());
            }
        }
    }

    // プランツールの条件付き追加
    if config.plan_tool {
        tools.push(PLAN_TOOL.clone());
    }

    // Web検索ツールの条件付き追加
    if config.web_search_request {
        tools.push(OpenAiTool::WebSearch {});
    }

    // MCPツールの統合
    if let Some(mcp_tools) = mcp_tools {
        add_mcp_tools_to_list(&mut tools, mcp_tools);
    }

    tools
}
```

```rust
fn add_mcp_tools_to_list(
    tools: &mut Vec<OpenAiTool>,
    mcp_tools: HashMap<String, mcp_types::Tool>,
) {
    let mut sorted_tools: Vec<_> = mcp_tools.into_iter().collect();
    sorted_tools.sort_by(|a, b| a.0.cmp(&b.0)); // fully-qualified nameでソート

    for (fully_qualified_name, mcp_tool) in sorted_tools {
        tools.push(OpenAiTool::Function(ResponsesApiTool {
            name: fully_qualified_name,
            description: mcp_tool.description.unwrap_or_default(),
            strict: false,
            parameters: convert_mcp_schema_to_json_schema(&mcp_tool.input_schema),
        }));
    }
}
```

```rust
/// Generic JSON‑Schema subset needed for our tool definitions
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(tag = "type", rename_all = "lowercase")]
pub(crate) enum JsonSchema {
    Boolean {
        #[serde(skip_serializing_if = "Option::is_none")]
        description: Option<String>,
    },
    String {
        #[serde(skip_serializing_if = "Option::is_none")]
        description: Option<String>,
    },
    /// MCP schema allows "number" | "integer" for Number
    #[serde(alias = "integer")]
    Number {
        #[serde(skip_serializing_if = "Option::is_none")]
        description: Option<String>,
    },
    Array {
        items: Box<JsonSchema>,
        #[serde(skip_serializing_if = "Option::is_none")]
        description: Option<String>,
    },
    Object {
        properties: BTreeMap<String, JsonSchema>,
        #[serde(skip_serializing_if = "Option::is_none")]
        required: Option<Vec<String>>,
        #[serde(
            rename = "additionalProperties",
            skip_serializing_if = "Option::is_none"
        )]
        additional_properties: Option<bool>,
    },
```

```rust
pub(crate) fn create_tools_json_for_chat_completions_api(
    tools: &Vec<OpenAiTool>,
) -> crate::error::Result<Vec<serde_json::Value>> {
    let responses_api_tools_json = create_tools_json_for_responses_api(tools)?;
    let tools_json = responses_api_tools_json
        .into_iter()
        .filter_map(|mut tool| {
            if tool.get("type") != Some(&serde_json::Value::String("function".to_string())) {
                return None;
            }
            if let Some(map) = tool.as_object_mut() {
                // "type" フィールドを削除し、chat completions形式に変換
                map.remove("type");
                Some(json!({
                    "type": "function",
                    "function": map,
                }))
            } else {
                None
            }
        })
        .collect::<Vec<serde_json::Value>>();
    Ok(tools_json)
}
```

## まとめ

Codex-CLIのツール定義システムは、以下の特徴により高度な拡張性と安全性を実現しています：

**技術的優位性**
- **型安全性**: Rustの型システムによる厳密な検証
- **動的適応**: モデルと環境に応じた最適なツール選択
- **統一インターフェース**: 異種ツールの透明な統合
- **セキュリティ統合**: サンドボックスと権限管理の組み込み

**拡張性**
- **MCP統合**: 外部ツールの動的取り込み
- **プラガブル設計**: 新しいツール型の追加容易性
- **API変換**: 異なるモデルAPIへの適応

**実用性**
- **詳細なドキュメント**: ツール使用方法の明確な説明
- **エラー処理**: 堅牢な例外処理とフィードバック
- **パフォーマンス最適化**: 効率的なJSONシリアライゼーション

この設計により、Codex-CLIは多様な機能要求に対応しながら、一貫性と安全性を保持したツール実行環境を提供しています。
