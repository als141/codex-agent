## 概要

Codex-CLIのシステムプロンプトは、複数の層からなる階層構造を持っています。この設計により、基本的なエージェント機能から特定プロジェクトの要件まで、柔軟かつ一貫した指示体系を実現しています。

### プロンプト階層構造
```
最終システムプロンプト
├── BASE_INSTRUCTIONS (核となる指示)
├── Apply Patch Tool Instructions (条件付き)
├── User Instructions (設定由来)
└── Project Documentation (AGENTS.md)
```

## システムプロンプト構築プロセス

### 動的構築実装

**`codex-rs/core/src/client_common.rs`** (44-66行)
```rust
impl Prompt {
    pub(crate) fn get_full_instructions(&self, model: &ModelFamily) -> Cow<'_, str> {
        let base = self
            .base_instructions_override
            .as_deref()
            .unwrap_or(BASE_INSTRUCTIONS);
        let mut sections: Vec<&str> = vec![base];

        // Apply Patch Tool Instructionsの条件付き追加
        let is_apply_patch_tool_present = self.tools.iter().any(|tool| match tool {
            OpenAiTool::Function(f) => f.name == "apply_patch",
            OpenAiTool::Freeform(f) => f.name == "apply_patch",
            _ => false,
        });
        
        if self.base_instructions_override.is_none()
            && (model.needs_special_apply_patch_instructions || !is_apply_patch_tool_present)
        {
            sections.push(APPLY_PATCH_TOOL_INSTRUCTIONS);
        }
        
        Cow::Owned(sections.join("\n"))
    }
}
```

### 構築の優先順位

**1. ベース指示の確定**
- デフォルト: `BASE_INSTRUCTIONS` (prompt.md)
- オーバーライド可能: `base_instructions_override`

**2. ツール固有指示の追加**
- Apply Patchツール用の特別指示
- モデル固有要件の考慮

**3. セクション結合**
- 改行区切りで各セクションを連結
- 動的な条件判定による最適化

## ユーザー指示の統合

### プロジェクトドキュメント統合

**`codex-rs/core/src/project_doc.rs`** (23-38行)
```rust
pub(crate) async fn get_user_instructions(config: &Config) -> Option<String> {
    match read_project_docs(config).await {
        Ok(Some(project_doc)) => match &config.user_instructions {
            Some(original_instructions) => Some(format!(
                "{original_instructions}{PROJECT_DOC_SEPARATOR}{project_doc}"
            )),
            None => Some(project_doc),
        },
        Ok(None) => config.user_instructions.clone(),
        Err(e) => {
            error!("error trying to find project doc: {e:#}");
            config.user_instructions.clone()
        }
    }
}
```

### プロジェクトドキュメント発見メカニズム

**AGENTS.mdファイルの検索**
```rust
const PROJECT_DOC_SEPARATOR: &str = "\n\n--- project-doc ---\n\n";
```

**検索戦略**
1. 現在の作業ディレクトリ
2. Gitリポジトリルート（`.git`ディレクトリ検出）
3. 階層的検索（ルートから現在ディレクトリまで）

**統合ルール**
- 設定の`user_instructions` + プロジェクト区切り + `AGENTS.md`内容
- 設定が存在しない場合は`AGENTS.md`のみ
- 両方存在しない場合は`None`

## まとめ

Codex-CLIのシステムプロンプト実装は、以下の特徴により高度な柔軟性と保守性を実現しています：

**アーキテクチャの優位性**
- **階層化設計**: ベース→ツール固有→ユーザー→プロジェクト
- **動的構築**: モデル機能とツール状態に応じた最適化
- **設定駆動**: 環境や用途に応じた調整可能性

**実用性**
- **プロジェクト統合**: AGENTS.mdによる自動カスタマイズ
- **スケーラビリティ**: 大規模プロジェクト対応のサイズ制限
- **保守性**: モジュール化された責任分離

**拡張性**
- **プラガブル設計**: 新しいモデルやツールへの対応
- **条件付き機能**: 環境に応じた最適化
- **設定フレキシビリティ**: 多様な利用シナリオ対応

この設計により、Codex-CLIは様々な開発環境やプロジェクト要件に対して一貫性のあるエージェント体験を提供しています。
